## BOSQICH 11 — Qidiruv va keng filtrlar

**Fayllar:** `discovery/search.*`, `catalogs/filter-options.*` (zaruratga qarab modul ichida), query schema.

**Manbadagi filter guruhlari:** masofa, reyting, o‘yin, hardware (monitor Hz/GPU/CPU/RAM), xona turi, xizmatlar, narx, ish vaqti/mavjudlik.

**Vazifalar**
- [ ] `GET /api/v1/clubs` uchun oddiy `q`, `city`, `page`, `limit`, `sort`.
- [ ] Keng filtr kerak bo‘lsa manbadagi `POST /api/v1/search` kontraktini ishlat; query/body schema yarat.
- [ ] `GET /api/v1/filters/options` orqali o‘yinlar, mavjud xona turlari va filter variantlarini qaytar.
- [ ] Filterlarni birlashtirish: guruhlar orasida odatda `AND`, bitta ro‘yxat ichida `IN/ANY` (OR). Bu API kontraktida aniq yozilsin.
- [ ] Jihoz/o‘yin/xizmat filtrlarida `EXISTS`dan foydalanishni ko‘rib chiq; JOIN sabab bitta club bir necha marta chiqmasin.
- [ ] Min/max narx, reyting, refresh rate, masofa va hozir ochiq filtrlari uchun edge testlar yoz.
- [ ] Paginatsiyada `total`, takrorlanmaydigan tartib (`id` tie-breaker) va limit maksimumi bo‘lsin.
- [ ] Dinamik SQL tuzishda foydalanuvchi qiymatlari bind parameter bo‘lsin; SQL identifikatorlari uchun allowlist ishlat.

**Backend misol kontrakti (tavsiya):**

```json
{
  "q": "cyber",
  "location": {"lat": 39.6542, "lng": 66.9597, "radiusMeters": 5000},
  "ratingMin": 4,
  "games": ["cs2", "dota2"],
  "hardware": {"screenHzMin": 144, "ramGbMin": 16},
  "roomTypes": ["vip_zone"],
  "services": ["parking", "wifi"],
  "price": {"min": 10000, "max": 50000},
  "openNow": false,
  "page": 1,
  "limit": 20,
  "sort": "distance"
}
```

**Frontend chegarasi:** foydalanuvchi tanlayotgan `draftFilters` va qo‘llangan `appliedFilters` — frontda. SQL qidiruvi, validatsiya, sahifalash — backendda. URL/query serialize qilishni frontend bilan API kontraktida kelishib ol.

**Qabul mezonlari:** kamida 3–4 filtr birgalikda ishlaydi; bitta club dublikat bo‘lib chiqmaydi; sort va page barqaror.
