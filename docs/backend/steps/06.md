## BOSQICH 06 — JWT, refresh token, RBAC va obyekt ruxsatlari

**Fayllar:** `auth.service.ts`, `authenticate.ts`, `authorize.ts`, token/sessiya migratsiyalari.

**Vazifalar**
- [ ] `jose` orqali qisqa muddatli access JWT; issuer, audience, expiry tekshiruvlari.
- [ ] Refresh token strategiyasini tanla: rotatsiya, serverda xeshlangan token/session, logoutda bekor qilish (eski refresh qayta ishlatilishini aniqlash).
- [ ] `POST /api/v1/auth/refresh`, `POST /api/v1/auth/logout`, `GET /api/v1/users/me`ni yoz.
- [ ] `user`, `club_owner`, `admin` huquqlarini markazlashtir.
- [ ] Faqat role yetmaydi: clubni tahrirlashda `club.owner_id === authenticatedUser.id`ni service darajasida tekshir.
- [ ] Admin huquqini client so‘rovi bilan berishni taqiqlash.
- [ ] Login/refresh uchun rate limit va maxfiy xabarlarni testdan o‘tkaz.

**Qabul mezonlari:** token bo‘lmasa 401; oddiy user owner API'ga kira olmaydi 403; logoutdan keyin refresh bekor bo‘ladi; begona clubni o‘zgartirib bo‘lmaydi.

### Boshlang‘ich ruxsatlar matritsasi

| Amal | user | club_owner | admin |
|---|:---:|:---:|:---:|
| Tasdiqlangan clublarni ko‘rish/qidirish | ✓ | ✓ | ✓ |
| Favorites / izoh qoldirish | ✓ | ✓ | ✓ |
| Club yaratish uchun murojaat | * | ✓ | ✓ |
| O‘z clubini tahrirlash | — | ✓ | ✓ |
| Boshqa egaga tegishli clubni tahrirlash | — | — | ✓ |
| Clubni tasdiqlash/rad etish | — | — | ✓ |
| Rollarni/foydalanuvchilarni boshqarish | — | — | ✓ |

`*` — yangi foydalanuvchi qachon `club_owner`ga aylanishi alohida workflow bilan tasdiqlanishi shart (qarorlar bo‘limi).
